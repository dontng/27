## 整体框架

内容按两个维度管理，不要混在一起：

```text
纵向：功能分层（同一份知识，不同用途要分开文件）
   理解(concept) ── 为什么是这样，概念怎么连起来
   记忆(recite)  ── 压缩成能默写的最小单元
   答题(answer)  ── 设问类型 → 答案结构，跨学科通用，不按学科重复
   诊断(drill)   ── 真实限时作答 → 找断点 → 反过来改前两层
   复习(review)  ── 间隔重复的调度，只做入口，不重复内容

横向：学科颗粒度（管理单元是学科内部的理论板块，不是整科打包）
   马原 → 马哲 / 政经 / 科社（已验证的切法）
   其余五科 → 各自按内在逻辑切，见 src/ 下各自 README
```

当前只有"理解"和"记忆"两层在用，且只验证到"马原三块能不能串成一条逻辑链"——还没有用真实限时材料题验证过它们能不能转化成选择题/分析题的实际得分。这正是上面那段要解决的问题，是下一步，不是知识覆盖的扩大。

## 现实约束

备考时间不是连续、可预期的一段——在职、加班、随时可能被工作打断好几天。所以这里的内容要能单次会话内用完一个独立单元，不依赖"先攒出一整块空闲时间"才能开始；也不会为了显得"全覆盖"而提前把六科目录铺满空内容，哪个颗粒度被真实卷面问题或真题命中了，才去展开那一块。
